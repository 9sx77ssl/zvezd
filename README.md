# zvezd

Авто-раздача звёзд в халява-разделе форума lolz.team. Пользователи кидают в
отслеживаемую тему ссылку на свой Telegram-пост или канал; бот выдаёт за это
оплаченную звезду, подтверждает выдачу комментарием, добавляет рекламу и ведёт
публичную тему со статистикой (лидерборд, баланс, пересечения каналов). Взамен
участники ставят симпатии/активность — это self-hosted промо-инструмент, а не
библиотека.

## Требования

- [Bun](https://bun.sh) >= 1.4
- аккаунт lolz.team с API-токеном (права `read` и `post`)
- данные Telegram-приложения (`api_id`, `api_hash`) и авторизованная сессия

## Установка

```bash
bun install
cp .env.example .env
```

`.env` хранит **только ключи**:

- `FORUM_TOKEN` — bearer-токен API lolz.team;
- `TG_API_ID`, `TG_API_HASH` — из https://my.telegram.org/apps.

Всё поведение (лимиты, задержки, тексты, темы, пути) — в `config.yml`; у каждой
переменной там короткий русский комментарий.

## Авторизация Telegram

Один раз выполни интерактивный вход:

```bash
bun run login
```

Появится запрос телефона/кода/2FA, после чего сессия сохранится в файл из
`telegram.sessionPath` (`./data/tg.session` по умолчанию). Файл сессии — секрет,
не коммить его. Дальше бот работает без интерактива.

## Запуск

```bash
bun run start     # рабочий запуск
bun run dry       # симуляция без трат звёзд (флаг --dry)
bun run dev       # запуск с авто-перезагрузкой
```

## Команды

| Команда | Что делает |
|---|---|
| `bun run start` | запустить бота |
| `bun run dry` | симуляция без реальных трат |
| `bun run dev` | dev-режим с watch |
| `bun run login` | авторизовать Telegram-сессию |
| `bun run typecheck` | проверка типов (`tsc --noEmit`) |
| `bun run lint` / `lint:fix` | линт/формат через Biome |
| `bun test` | тесты |

## Как это работает

1. Сканер обходит тему (на старте — беклог, дальше — опрос новых страниц;
   незавершённые посты периодически повторяются).
2. Для каждого нового поста выполняются проверки (`src/issuance/checks.ts`):
   первый пост, удалённые/скрытые и свои посты отбрасываются; отсутствие ссылки,
   выключенные платные реакции, пустой канал и нерезолвящуюся ссылку — бот
   сообщает пользователю и всё равно ставит рекламу.
3. Если в посте несколько ссылок, бот перебирает их по порядку (ссылки не на Telegram,
   вроде YouTube, отбрасываются) и ставит звезду только на **первую** подходящую
   (резолвится и принимает платные реакции). Если рабочих ссылок несколько, звезда
   всё равно одна, а в подтверждение дописывается `comment.multipleLinksText`.
4. Иначе бот ставит звезду (идемпотентно, состояние хранится в SQLite) и пишет
   комментарий-подтверждение и рекламу.
5. Все действия разнесены общим кулдауном (`pacing.cooldownMs`), лимиты API
   соблюдают токен-бакеты (`rateLimit.*`).
6. `StatsService` раз в `stats.intervalMs` переписывает заголовок и первый пост
   темы статистики.

Единый словарь статусов/причин/уведомлений — `src/core/vocab.ts`. Чтобы добавить
уведомление, достаточно строки в `NOTICES`, текста в `comment.*` и класса
ошибки; тихая проверка — строка в `PRE_CHECKS`.

## Деплой (pm2)

```bash
pm2 start ecosystem.config.cjs
pm2 restart zvezd
```

PM2-конфиг сам находит `bun` (или берёт путь из `BUN_PATH`).
