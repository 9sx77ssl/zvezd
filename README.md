# Lolz Star Bot

Бот для lolz.team: следит за темой форума, находит в постах ссылки на Telegram,
ставит звезду на пост/канал, пишет подтверждение и рекламу, ведёт базу и
публикует живую тему со статистикой.

## Требования

- [Bun](https://bun.sh) >= 1.4
- аккаунт lolz.team с API-токеном (права `read` и `post`)
- данные Telegram-приложения (`api_id`, `api_hash`) и авторизованная сессия

## Установка

```bash
bun install
cp .env.example .env
```

Заполни `.env`:

- `FORUM_TOKEN` — bearer-токен API lolz.team;
- `TG_API_ID`, `TG_API_HASH` — из https://my.telegram.org/apps.

Основные настройки поведения — в `config.yml` (там у каждой переменной короткий
русский комментарий). Переменные из `.env` имеют приоритет над `config.yml`.

## Авторизация Telegram

Один раз выполни интерактивный вход:

```bash
bun run login
```

Появится запрос телефона/кода/2FA, после чего сессия сохранится в файл из
`telegram.sessionPath` (`./data/tg.session` по умолчанию). Файл сессии — секрет,
не коммить его. Дальше бот работает без интерактива.

Чтобы Telegram-логин не требовал форумный токен, сначала заполни `.env`
полностью (и `FORUM_TOKEN`, и Telegram-данные).

## Запуск

```bash
bun run start     # рабочий запуск
bun run dry       # симуляция без трат звёзд (DRY_RUN=true)
bun run dev       # запуск с авто-перезагрузкой
```

## Команды

| Команда | Что делает |
|---|---|
| `bun run start` | запустить бота |
| `bun run dry` | симуляция без реальных трат |
| `bun run dev` | dev-режим с watch |
| `bun run login` | авторизовать Telegram-сессию |
| `bun run typecheck` | проверка типов (`tsc --noEmit`) |
| `bun run lint` / `lint:fix` | линт/формат через Biome |
| `bun test` | тесты |

## Как это работает

1. Сканер обходит тему (на старте — беклог, дальше — опрос новых страниц).
2. Для каждого нового поста выполняются проверки (`src/issuance/checks.ts`):
   первый пост, удалённые/скрытые, свои посты отбрасываются; отсутствие ссылки,
   выключенные платные реакции, пустой канал и нерезолвящаяся ссылка дают
   уведомление пользователю + рекламу.
3. Иначе бот ставит звезду (идемпотентно, с persisted-состоянием в SQLite) и
   пишет комментарий-подтверждение и рекламу.
4. Все действия разнесены общим кулдауном (`pacing.cooldownMs`), а лимиты API
   соблюдаются токен-бакетами (`rateLimit.*`).
5. `StatsService` раз в `stats.intervalMs` переписывает заголовок и первый пост
   темы статистики.

Единый словарь статусов/причин/уведомлений — `src/core/vocab.ts`. Чтобы добавить
новое уведомление, достаточно строки в `NOTICES`, текста в `comment.*` и класса
ошибки; чтобы добавить тихую проверку — строки в `PRE_CHECKS`.
